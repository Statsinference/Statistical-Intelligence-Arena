# Citation and authorship guidance (development draft)

**Project:** Statistical Inference Arena (StatsArena)  
**Status:** Internal research development; no approved publication citation, DOI or finalized author list in this repository snapshot.

## For internal presentations and notes

Use the project title **Statistical Inference Arena (StatsArena)**, label material as **in development**, and reference the relevant repository commit or protocol version when discussing reproducibility. Do not invent a paper title, publication date, BibTeX key, DOI or author order.

## For the first public release

The project leads should confirm, before publishing a `CITATION.cff`:

1. The **canonical software/benchmark title**, version and public repository URL.
2. The approved **software citation authors** (or a suitable named group), with names and identifiers verified by the team.
3. The planned relationship between **task contributors, scientific reviewers, repository maintainers, software citation authors and future paper authors**. These categories are not automatically identical.
4. Whether a **specific version DOI** exists (for example via a versioned archive). Do not claim one before it has been minted.
5. A release and licensing decision for the benchmark, public DGPs, data and other redistributed assets.

At that point, add a valid `CITATION.cff` to the repository root to enable GitHub's **Cite this repository** interface. When an associated paper is actually published, update the preferred citation as approved by the team. Keep a stable version-specific reference for reproducibility.

## Contribution recognition

Track task authorship and review in the PR and documentation, including precise scientific and implementation contributions. GitHub commits or Organization Owner status do not determine paper authorship. Agree on credit and any required review before public release.
